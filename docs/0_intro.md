# ВСТУП

## Актуальність теми

Розвиток квантових обчислень ставить під загрозу асиметричні криптографічні примітиви (RSA, ECC, ECDSA), стійкість яких ґрунтується на складності задач факторизації та дискретного логарифмування. Алгоритм Шора розв'язує ці задачі за поліноміальний час, що робить недійсними цифрові підписи та механізми обміну ключами у чинних системах електронного документообігу. Загроза «Harvest Now, Decrypt Later» означає, що зашифровані документи з тривалим терміном конфіденційності можуть бути перехоплені сьогодні й розшифровані після появи достатньо потужного квантового комп'ютера. Національний інститут стандартів і технологій США (NIST) стандартизував постквантові алгоритми ML-KEM (FIPS 203) і ML-DSA (FIPS 204), проте їх інтеграція у розподілені системи пов'язана з інженерними обмеженнями: збільшенням розмірів ключів і підписів, зростанням затримок обробки та необхідністю гібридних схем для збереження зворотної сумісності.

Додаткову інженерну проблему становить контроль якості ентропії та генераторів псевдовипадкових чисел (PRNG), оскільки стійкість будь-якої криптосхеми визначається статистичною якістю ключового матеріалу. Реалізація повного життєвого циклу документа у мікросервісній подієво-орієнтованій архітектурі вимагає забезпечення відмовостійкості (Fault Tolerance), горизонтальної масштабованості, незмінності журналу подій безпеки та контролю цілісності сховища в умовах моделі Zero Trust. Використання Java 21 / Bouncy Castle та liboqs для криптографічного ядра, Python / FastAPI для сервісу управління документами, Apache Kafka для журналу подій, MinIO S3 з деревами Меркла для контролю цілісності та CI/CD-конвеєра з автоматизованим аналізом безпеки коду й контейнерів дає змогу розв'язати зазначені задачі комплексно.

## Об'єкт дослідження

Процес захищеного зберігання, обміну та підтвердження автентичності корпоративних електронних документів в умовах квантових загроз.

## Предмет дослідження

Методи та алгоритми постквантової криптографії (ML-KEM, ML-DSA), гібридна схема шифрування ML-KEM + AES-256-GCM, статистичні тести NIST STS для оцінювання якості ентропії ключів, моделі контролю доступу RBAC/ABAC, контроль цілісності даних на основі дерев Меркла, а також архітектурні патерни (Мікросервіси, Event-Driven Architecture, Zero Trust, Clean Architecture, Repository, Circuit Breaker), що застосовуються для захисту процесу обігу електронних документів.

## Мета роботи

Проєктування та розробка криптографічно захищеної системи документообігу на основі постквантових алгоритмів ML-KEM і ML-DSA, гібридного шифрування та автоматизованого аудиту випадковості ключів NIST STS, з метою забезпечення стійкості конфіденційності, цілісності й автентичності документів до атак із використанням квантових обчислень за мінімального зниження продуктивності відносно класичних схем (RSA, ECDSA) та збереження відмовостійкості мікросервісної архітектури.

## Завдання проєкту

1. Проаналізувати існуючі системи електронного документообігу та реалізації постквантової криптографії (аналоги) за критеріями криптографічної стійкості, продуктивності, відмовостійкості та відповідності стандартам NIST FIPS 203/204, оформивши результати згідно з ДСТУ 3008:2015.
2. Обґрунтувати вибір технологічного стеку (Python 3.11+, Java 21, FastAPI, Spring Boot/Quarkus, Bouncy Castle, liboqs, MySQL, MinIO, Apache Kafka, Docker) та криптографічних параметрів (набори параметрів ML-KEM і ML-DSA, режим AES-256-GCM).
3. Спроєктувати архітектуру мікросервісної подієво-орієнтованої системи (Auth & IAM, PQC Core Engine, служба управління документами, служба аудиту NIST STS, рівень зберігання) із використанням UML-діаграм та моделі C4, з урахуванням принципів Zero Trust і Clean Architecture.
4. Розробити алгоритми критичних вузлів: гібридного шифрування документа (ML-KEM + AES-256-GCM), підписання та верифікації ML-DSA, аудиту ентропії ключів за NIST STS, контролю цілісності на деревах Меркла та публікації подій безпеки в Apache Kafka.
5. Розробити програмний інтерфейс (REST API) системи та схему розгортання на базі Docker і Docker Compose з налаштуванням CI/CD-конвеєра (GitHub Actions) і автоматизованим аналізом безпеки коду та контейнерів (SonarQube, Trivy).
6. Виконати інструментальний аудит системи: модульне та інтеграційне тестування (PyTest, JUnit 5), навантажувальне тестування (Locust/k6) з вимірюванням затримок і пропускної здатності, перевірку відмовостійкості та статистичну оцінку якості ключів за NIST STS.
7. Провести науково-практичну апробацію результатів, порівняти гібридну схему з класичними алгоритмами (RSA, ECDSA) за показниками продуктивності та розміром артефактів, підготувати наукову публікацію за результатами дослідження.
