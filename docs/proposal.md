# Thesis Proposal

> Кваліфікаційний проєкт бакалавра
> Спеціальність F2 — Інженерія програмного забезпечення

---

## 1. Робоча назва проєкту

* **UA:** Розробка криптографічно захищеної системи документообігу з підтримкою постквантових стандартів безпеки
* **EN:** Development of a Cryptographically Secure Document Management System Supporting Post-Quantum Security Standards
---

## 2. Актуальність та проблематика

Стрімкий розвиток квантових обчислювальних потужностей створює загрозу недійсності класичних асиметричних криптоалгоритмів (RSA, ECDSA, ECC) через їхню вразливість до квантового алгоритму Шора. Корпоративні та державні системи документообігу стикаються із загрозою «Harvest Now, Decrypt Later» (масове перехоплення та збереження зашифрованого трафіку з метою його розшифрування в майбутньому після появи повномасштабного квантового комп'ютера).

Традиційні рішення електронного документообігу (ЕДО) стикаються з трьома основними інженерно-технічними проблемами:
1. **Квантова вразливість цифрового підпису та шифрування** — компрометація традиційних алгоритмів робить неможливим довгострокове підтвердження авторства та цілісності юридично значущих документів.
2. **Проблема генерації слабкої ентропії та псевдовипадкових ключів** — відсутність вбудованого автоматизованого контролю якості генераторів псевдовипадкових чисел (PRNG) створює критичні вразливості на етапі створення системних ключів шифрування.
3. **Складність міграції на постквантові стандарти без втрати продуктивності** — необхідність поєднання постквантових алгоритмів NIST із класичними криптопримітивами (гібридні схеми) в умовах високих вимог до швидкодії вебплатформ.

**Інженерна проблематика:** Складність задачі полягає в проєктуванні відмовостійкої мікросервісної системи, яка забезпечує повний життєвий цикл документа (створення, гібридне шифрування, постквантовий підпис) із паралельним проведенням математичного аудиту якості ключів через комплекс NIST STS та збереженням працездатності в Zero-Trust середовищі.

---

## 3. Сформована ідея продукту

**Тип системи за архітектурою:** криптографічно захищена розподілена платформа корпоративного документообігу, побудована за принципами Zero Trust та Privacy by Design.

Архітектурно система є мікросервісною подієво-орієнтованою (Event-Driven) платформою, що складається з: 

- **Auth & IAM Service:** сервіс автентифікації на основі OAuth2/JWT з розмежуванням доступу (RBAC/ABAC).
- **PQC Core Engine (Java/Bouncy Castle):** виділений сервіс виконання постквантових криптографічних операцій (ML-KEM, ML-DSA).
- **Document Management Service (Python/FastAPI):** сервіс бізнес-логіки обробки, підписання та шифрування документів.
- **NIST STS Audit Service:** автономний аналітичний модуль тестування випадковості ентропії ключів.
- **Storage & Integrity Layer:** об'єктне сховище MinIO S3 із контролем цілісності файлів на основі дерев Меркла (Merkle Trees).
---

## 4. Детальний опис функціоналу (Core Features)

1. **Механізм постквантового цифрового підпису (ML-DSA):** створення та верифікація електронного цифрового підпису документів із використанням стандартизованого NIST постквантового алгоритму ML-DSA (Dilithium) для гарантування довгострокової невідреченості (non-repudiation).
2. **Сервіс гібридного шифрування документів (ML-KEM + AES-256-GCM):** реалізація гібридної схеми шифрування документів: інкапсуляція симетричного ключа за допомогою постквантового алгоритму ML-KEM (Kyber) та подальше шифрування вмісту документа за допомогою AES-256-GCM.
3. **Автоматизований аудит випадковості ключів (NIST STS):** вбудований сервіс статистичного аналізу пакета створених ключів шифрування за допомогою тестувального комплексу NIST Statistical Test Suite з формуванням електронного звіту ентропії.
4. **Контроль доступу за моделлю «нульової довіри» (RBAC/ABAC):** розмежування прав доступу до документів на рівні API за допомогою ролей та атрибутів (посада, рівень доступу, гриф секретності, часовий інтервал).
5. **Secure Object Storage with Merkle Tree Integrity:** збереження шифрованих файлів у MinIO S3 із фоновою верифікацією хеш-дерев для миттєвого виявлення фактів пошкодження або підміни бінарних даних.
6. **Auditable Security Event Logging:** фіксація всіх криптографічних операцій та спроб доступу у незмінному журналі аутентифікованих подій з асинхронною передачею через Apache Kafka.
7. **DevSecOps Compliance & Vulnerability Scanner Integration:** автоматичний контроль контуру безпеки коду та конфігурацій контейнерів на етапі CI/CD збірки.

## 5. Обґрунтування технологічного стеку

| Категорія | Обрані технології 
| :--- | :--- | 
| **Мови програмування** | Python 3.11+ (Backend API & Logic), Java 21 (Cryptographic Provider Service) |
| **Архітектурні патерни** | Microservices Architecture, Event-Driven Architecture, Zero Trust, Clean Architecture, Repository Pattern, Circuit Breaker | 
| **Криптографічні бібліотеки** | Bouncy Castle PQC API (Java), PyCryptodome, OQS (Open Quantum Safe) C-bindings / liboqs | 
| **Алгоритми та стандарти** | RNIST ML-KEM (Kyber), NIST ML-DSA (Dilithium), AES-256-GCM, SHA-3, NIST STS (Statistical Test Suite) | 
| **Backend-фреймворки** | FastAPI (Python), Spring Boot / Quarkus (Java Crypto-Service) | 
| **Бази даних та сховища** | MySQL (реляційна БД для зберігання метаданих користувачів, прав доступу, сесій та журналу аудиту безпеки), Local Encrypted File System (локальна файлова система з шифруванням вмісту документів)|
| **Обмін повідомленнями** | Apache Kafka (асинхронне логування подій безпеки та запусків аудиту ентропії) |
| **DevSecOps та CI/CD** | Docker, Docker Compose, GitHub Actions, Trivy (сканер вразливостей контейнерів), SonarQube (Static Application Security Testing) |
| **Тестування та якість** | PyTest, JUnit 5, NIST STS Suite, Locust / k6 (навантажувальне тестування крипто-модулів) |

### DevOps, інженерія якості та спостережуваність

- **Docker, Docker Compose:** Контейнеризація сервісів (auth-iam-service, pqc-core-engine, document-service, nist-sts-audit-service, kafka, mysql, minio) та оркестрація локального середовища розробки з ізольованою внутрішньою мережею за принципом Zero Trust.
- **GitHub Actions:** Конвеєр безперервної інтеграції (CI) для автоматичного запуску лінтерів, тестів, статичного аналізу безпеки та сканування контейнерів при кожному push/PR.
- **PyTest, JUnit 5, coverage.py / JaCoCo:** Автоматизоване unit- та integration-тестування REST API (Python), криптографічного провайдера (Java) і контрактів обміну через Kafka з контролем покриття коду. Верифікація криптографічних модулів за відомими тестовими векторами NIST (Known Answer Tests для ML-KEM та ML-DSA).
- **Ruff, mypy:** Статичний аналіз, автоматичне форматування та сувора перевірка типізації Python 3.11+.
- **SonarQube (SAST):** Статичний аналіз безпеки вихідного коду (Python та Java): пошук вразливостей, вразливих залежностей і «запахів» коду з блокуванням PR за невиконання Quality Gate.
- **Trivy:** Автоматичне сканування Docker-образів та залежностей на наявність відомих вразливостей (CVE) у конвеєрі CI/CD.
- **NIST STS:** Статистичний аудит випадковості ентропії згенерованих ключів з автоматичним формуванням звіту за результатами 15 тестів комплексу.
- **Locust / k6:** Навантажувальне тестування криптографічних операцій (підписання, шифрування, верифікація) для оцінки накладних витрат гібридної схеми порівняно з класичними RSA/ECDSA.
- **Prometheus, Grafana:** Збір та візуалізація системних метрик (CPU/RAM) і специфічних метрик криптосервісів (латентність ML-KEM/ML-DSA, пропускна здатність підписання, частка невдалих верифікацій, лаг споживачів Kafka).
- **OpenTelemetry:** Наскрізне розподілене трасування запитів між auth-iam-service, document-service та pqc-core-engine.
- **Alembic / Flyway:** Версіонування та безпечне застосування міграцій схеми MySQL (метадані, права доступу, журнал аудиту).

## 6. Документування проєкту

- **Documentation as Code:** Зберігання всієї проєктної та технічної документації у форматі Markdown у Git-репозиторії поруч із вихідним кодом.
- **OpenAPI 3.0 (FastAPI docs / springdoc-openapi):** Автоматична генерація та інтерактивна публікація специфікації REST API для document-service та pqc-core-engine.
- **Architecture Decision Records (ADR):** Фіксація та версіонування критичних архітектурних рішень (вибір ML-KEM та ML-DSA, гібридна схема з AES-256-GCM, виділення криптографії в окремий Java-сервіс, вибір Kafka для незмінного журналу аудиту).
- **Threat Model (STRIDE):** Формалізація моделі загроз системи, зокрема атак класу «Harvest Now, Decrypt Later», і відповідних контрзаходів.
- **C4 Model (Structurizr / PlantUML):** Візуалізація архітектури на рівнях System Context, Container (взаємодія сервісів) та Component (внутрішня структура pqc-core-engine і document-service).

## 7. Очікувані результати

1. **Працездатна криптографічно захищена платформа документообігу:** Повнофункціональна вебсистема з рольовим та атрибутним розмежуванням доступу (RBAC/ABAC) в архітектурі Zero Trust, що підтримує повний життєвий цикл документа: створення, шифрування, підписання, зберігання та верифікацію.
2. **Постквантове криптографічне ядро:** Виділений сервіс на базі Bouncy Castle, що реалізує цифровий підпис ML-DSA та інкапсуляцію ключів ML-KEM у гібридній схемі з AES-256-GCM.
3. **Автоматизований аудит ентропії ключів:** Автономний сервіс, що проганяє пакети згенерованих ключів через NIST Statistical Test Suite та формує електронний звіт якості випадковості.
4. **Захищене сховище з контролем цілісності:** Шифроване зберігання документів у MinIO S3 із фоновою верифікацією дерев Меркла для виявлення пошкодження або підміни бінарних даних.
5. **Подієво-керований контур аудиту безпеки:** Незмінний журнал криптографічних операцій і спроб доступу з асинхронною передачею через Apache Kafka та патерном Circuit Breaker у міжсервісній взаємодії.
6. **Автоматизований конвеєр DevSecOps (CI/CD):** Налаштовані GitHub Actions зі статичним аналізом (Ruff/mypy, SonarQube), автоматичним тестуванням (PyTest, JUnit 5) та скануванням вразливостей контейнерів (Trivy).
7. **Контур спостережуваності (Observability):** Моніторинг метрик криптографічних операцій у Prometheus/Grafana та наскрізне трасування запитів через OpenTelemetry.
8. **Комплект технічної документації:** Специфікація OpenAPI, ADR-записи, C4-діаграми, модель загроз та пояснювальна записка з формалізацією криптографічних схем і результатами навантажувального тестування та порівняння з класичними алгоритмами.
